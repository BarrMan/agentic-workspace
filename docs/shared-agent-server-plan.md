## Runtime choices

- Independent local TUIs share normal tmux or the existing configured socket override. No required new daemon, app-specific socket setting or per-frontend server. <!-- consolidation: exists; ref: docs/BLUEPRINT.md#launch-context-and-shared-terminal-transport; reason: Explicit shared backend selection and configured override without per-frontend servers. -->
- Each UI owns its selection. Shared `activeSessionId` is a history preference, not execution selection <!-- consolidation: discard; ref: docs/BLUEPRINT.md#models-and-relationships; reason: Task owns durable mode/session selection while UI owns focus and attachment. --> or another frontend's teardown authority. <!-- consolidation: exists; ref: docs/BLUEPRINT.md#launch-context-and-shared-terminal-transport; reason: Selection does not grant exclusive runtime ownership. -->
- Distinct conversations in the same task/mode may run independently. <!-- consolidation: exists; ref: docs/BLUEPRINT.md#launch-context-and-shared-terminal-transport; reason: Independent same-mode conversations are explicit. --> Multiple clients may attach to one verified runtime; its input and terminal sizing are shared intentionally. <!-- consolidation: exists; ref: docs/BLUEPRINT.md#launch-context-and-shared-terminal-transport; reason: Shared input and sizing are explicit. -->
- New, live attach and stopped resume are distinct. <!-- consolidation: exists; ref: docs/BLUEPRINT.md#resume-attachment-and-hand-off; reason: Creation resume and terminal attachment are separate operations. --> The authorized AoE-style policy automatically resumes the saved native ID, with fresh-session fallback when it fails; successful resume preserves the exact ID and configuration, fallback may use a new ID. <!-- consolidation: discard; ref: docs/specs/sessions.md#stop-and-resume-a-session; reason: Exact resume uses current configuration and fresh conversation requires explicit consent. --> The setting and failed-resume marker data model are represented in `src/agent-workspace/types.ts`, `src/agent-workspace/config.ts`, and `src/agent-workspace/sessions.ts`; remaining policy work is phases 3–4 in the [handoff](shared-agent-runtime-handoff.md#immediate-remaining-proof). <!-- consolidation: discard; ref: none; reason: Historical implementation queue. --> An absent frontend is not evidence that execution stopped. <!-- consolidation: exists; ref: docs/specs/sessions.md#observe-and-detach-from-a-live-session; reason: Client loss does not establish agent exit. -->
- Quit/detach disposes UI transport, not the agent. <!-- consolidation: exists; ref: docs/specs/sessions.md#observe-and-detach-from-a-live-session; reason: Detach preserves agents. --> Agents survive until natural termination or explicit stop. No idle, last-client or finish-then-clean garbage collection. <!-- consolidation: discard; ref: docs/specs/sessions.md#enforce-the-running-session-soft-limit; reason: Blanket idle-stop prohibition conflicts with approved soft-limit eviction while detach safety remains. -->
- Reopen reloads shared records and discovers surviving runtimes. <!-- consolidation: exists; ref: docs/specs/sessions.md#observe-and-detach-from-a-live-session; reason: Reattachment uses surviving execution and current screen. --> Necessary recovery is separately serialized; no latest-private-instance selection or exclusive frontend adoption. <!-- consolidation: exists; ref: docs/BLUEPRINT.md#launch-context-and-shared-terminal-transport; reason: Frontend selection is not exclusive execution ownership. --> Foreign target identity and backend transport/probe errors remain errors, not absence. <!-- consolidation: exists; ref: docs/BLUEPRINT.md#observation-stop-and-deletion; reason: Probe failure and foreign provenance cannot prove absence. -->
- CLI/headless execution uses the same shared runtime and persistent lifetime. <!-- consolidation: exists; ref: docs/BLUEPRINT.md#component-ownership; reason: Supported surfaces share application and runtime owners. --> History/output reads start no infrastructure. <!-- consolidation: discard; ref: docs/specs/sessions.md#observe-and-detach-from-a-live-session; reason: Stored terminal-output retrieval is superseded. --> Ask retains its existing stopped-only, <!-- consolidation: exists; ref: docs/specs/supported-integration-operations.md#supported-integration-operations; reason: Ask is stopped-only. --> noninteractive timeout, partial-output and streaming contract. <!-- consolidation: unconfirmed; ref: docs/specs/supported-integration-operations.md#supported-integration-operations; reason: Exact ask timeout streaming and partial-output guarantees need supported-contract disposition. -->
