### Process-scoped status hooks

Status hooks are installed unconditionally at the shared launch chokepoint, so `agentic-workspace workspace`,
`agentic-workspace agent-session start`, and `agent-session … resume` produce identical launch artefacts: a
session created from the CLI is indistinguishable from one created by the workspace UI. The hooks
are process-scoped and owned exactly like the skill file:

## Presentation teardown: retain and change

Current tmux presentation distinguishes incidental detach from deliberate legacy quit. Incidental detach only detaches client and leaves pane processes alive ([`tmux-workspace.ts:956-964`](../src/agent-workspace/tmux-workspace.ts#L956-L964); [`tmux/client.ts:17-34`](../src/agent-workspace/tmux/client.ts#L17-L34)). OpenTUI changes deliberate workspace close:

1. Closing OpenTUI detaches and destroys renderer, controller subscriptions, timers, and view-state watcher. <!-- consolidation: exists; ref: docs/architecture/application-boundaries.md#ui-controller-feature-modules-renderer-and-terminal-host; reason: Client disposal releases UI transport and subscriptions only. -->
2. Closing OpenTUI MUST NOT call `AgentSessionService.stop`, `reset`, `reconcileTaskSessions`, `resumeLivePreviewPane`, or any `SessionProcess.kill*` method. <!-- consolidation: exists; ref: docs/architecture/application-boundaries.md#ui-controller-feature-modules-renderer-and-terminal-host; reason: UI close has no lifecycle effect regardless of source method names. -->
3. Closing OpenTUI MUST preserve every durable agent session and its tmux process for a later workspace reopen. <!-- consolidation: exists; ref: docs/specs/sessions.md#observe-and-detach-from-a-live-session; reason: Client exit leaves sessions running. -->
4. Explicit stop remains a durable service action. It is not teardown work. <!-- consolidation: exists; ref: docs/architecture/application-boundaries.md#application-controller; reason: Stop is a shared application operation. -->

Existing OpenTUI controller teardown already destroys its mount, renderer, and optionally owned view-state store without calling session lifecycle code ([`workspace-controller.ts:112-124`](../src/ui/opentui/workspace-controller.ts#L112-L124)). ## Stale-output rejection contract

Task selection is a security and correctness boundary for presentation. Current Blessed UI increments a selection generation, clears prior session state before asynchronous lookup, then accepts results only when generation and task still match ([`pane.ts:441-451`](../src/ui/workspace/pane.ts#L441-L451), [`pane.ts:460-515`](../src/ui/workspace/pane.ts#L460-L515)). <!-- consolidation: exists; ref: docs/architecture/application-boundaries.md#ui-controller-feature-modules-renderer-and-terminal-host; reason: Selection identity guards async results. --> <!-- consolidation: discard; ref: none; reason: Blessed source evidence is historical. -->

Every OpenTUI agent presentation request, result, and subscription event MUST carry this identity:

```ts
type AgentPresentationIdentity = {
	renderEpoch: number;
	taskId: string;
	sessionId?: string;
};

type AgentOutputEvent = AgentPresentationIdentity & {
	outputRevision: number;
};
```
<!-- consolidation: exists; ref: docs/architecture/application-boundaries.md#ui-controller-feature-modules-renderer-and-terminal-host; reason: AgentPresentationIdentity carries selected task/session and current selection generation. -->
<!-- consolidation: integrate; ref: docs/architecture/application-boundaries.md#ui-controller-feature-modules-renderer-and-terminal-host; reason: AgentOutputEvent additionally requires monotonically newer output revision for one identity. -->

Rules:

1. Increment `renderEpoch` synchronously before selecting a different task, changing displayed session, entering or leaving history/output mode, or tearing down controller. <!-- consolidation: integrate; ref: docs/architecture/application-boundaries.md#ui-controller-feature-modules-renderer-and-terminal-host; reason: Synchronous generation invalidation must precede task/session transition and teardown. --> <!-- consolidation: discard; ref: docs/specs/sessions.md#observe-and-detach-from-a-live-session; reason: Persisted transcript-history mode is superseded. -->
2. Clear right-pane task details, session identity, and live output synchronously before any async read or subscription replacement. <!-- consolidation: integrate; ref: docs/architecture/application-boundaries.md#ui-controller-feature-modules-renderer-and-terminal-host; reason: Explicit synchronous clearing before replacement reads is missing. -->
3. Commit an async result only when `renderEpoch`, `taskId`, and `sessionId` exactly match current presentation identity. <!-- consolidation: exists; ref: docs/architecture/application-boundaries.md#ui-controller-feature-modules-renderer-and-terminal-host; reason: Current generation and selected identity reject obsolete results. -->
4. For one identity, commit only an `outputRevision` newer than displayed revision. This prevents an older callback from overwriting newer output from same session. <!-- consolidation: integrate; ref: docs/architecture/application-boundaries.md#ui-controller-feature-modules-renderer-and-terminal-host; reason: Same-session output revision ordering is not explicit. -->
5. A session lifecycle update that changes active session ID creates a new identity. A sessionless state still carries task ID and current epoch. <!-- consolidation: integrate; ref: docs/architecture/application-boundaries.md#ui-controller-feature-modules-renderer-and-terminal-host; reason: Active-session changes and sessionless states retain complete presentation identity. -->
6. Drop every mismatched event silently. It may update no text, status, focus, footer, or error state for current selection. <!-- consolidation: exists; ref: docs/architecture/application-boundaries.md#ui-controller-feature-modules-renderer-and-terminal-host; reason: Obsolete results cannot update any replacement view state. -->

This extends existing task/session checks in history view and selection code. It fulfills specification rule that old output clears before new output commits and that late results for an unselected task are ignored ([`opentui-workspace-spec.md:90-103`](opentui-workspace-spec.md#L90-L103)). <!-- consolidation: discard; ref: none; reason: Historical rationale repeats the individually mapped stale-output rules. -->
