- **Removed public commands remain exposed.** Installed `agent-session --help` advertises `output` and `reconcile`; source still registers handlers at `src/commands/agent-workspace.ts:216–258`. This conflicts with SPEC's explicit removals. Neither command is restored to the review table. - **Configuration precedence differs from the owner's answer.** `src/agent-workspace/config.ts` — `resolveAgentConfiguration` and `projectOrParent` — selects a complete task configuration, otherwise a complete project configuration, otherwise its parent. This is not the approved consistent root < project < task field precedence. No nullable-clearing semantics, collection-policy questions, or private task modes are proposed here. <!-- consolidation: discard; ref: docs/specs/configuration.md#configuration-and-modes; reason: Whole-scope selection is superseded by field precedence with ACT-7 still open. -->
- **Task deletion differs from SPEC.** `src/core/task-lifecycle-service.ts` — `TaskLifecycleService.delete` — forgets task sessions and deletes the task container/references, rather than invoking the stop/worktree/branch cleanup used by `complete`. SPEC requires killing the task's agent and removing its worktree and branch. The observed deletion path is not a proposed replacement contract. <!-- consolidation: discard; ref: docs/specs/tasks.md#task-deletion; reason: Forget-only deletion is rejected explicitly with ACT-9 and DEC-1 retained. -->
- **Mode-settings deletion stages session moves.** `src/ui/opentui/mode-settings-draft.ts:159–170` queues a destination-mode move, wired to mode lifecycle handling in `src/ui/opentui/workspace-controller.ts` — `#openAgentSettings`. This conflicts with SPEC's no-merging and mode-session removal requirements; it is not listed as a feature awaiting approval. <!-- consolidation: discard; ref: docs/specs/configuration.md#delete-a-mode; reason: Session transfer conflicts with approved removal and ACT-8 remains open. -->
- **Handoff help states the wrong ordering.** Installed `agent-session handoff --help` says stop then start, contrary to SPEC's successor-first requirement. CLI-054 records command availability only; help wording does not prove actual execution ordering. <!-- consolidation: discard; ref: docs/specs/sessions.md#handoff; reason: Stop-first ordering is superseded by published successor first and ACT-10 remains unverified. -->
- **Draft lifecycle is explicitly rejected.** Help advertises draft commands and source implements promotion/demotion (`src/file-system/operations.ts:1007–1141`); SPEC states that tasks have no draft lifecycle. These commands are not pending requirements. <!-- consolidation: discard; ref: docs/specs/tasks.md#tasks-and-storage; reason: Direct task creation supersedes drafts and ACT-4 remains open. -->
- **Task discovery conflicts with the deterministic store.** `src/core/task-loader.ts` indexes branch candidates and `src/core/agentic-workspace.ts` scans same-repository worktrees; SPEC requires one deterministic project task store and no branch/worktree discovery. <!-- consolidation: discard; ref: docs/specs/tasks.md#tasks-and-storage; reason: Discovery conflicts with the authoritative project store and remains ACT-11 work. -->

SPEC defines approval as a mode indication, not artifact/hash approval, and says the application does not know or prescribe mode artifacts. <!-- consolidation: discard; ref: docs/specs/configuration.md#configuration-and-modes; reason: Task-mode indication and arbitrary outputs supersede artifact approval and declarations with ACT-13 open. -->

SPEC removes reset, board export, and the `--no-git` option.
