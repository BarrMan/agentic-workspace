## Deletion, in source order

1. **CLI remove path:** `cli/remove.rs::run` resolves the row. With `session.delete_to_trash` and no `--purge`, it trashes rather than purges. Otherwise flags feed `DeletionRequest` (`delete_worktree`, `delete_branch`, `force_delete`, sandbox/scratch options), `PurgeTransaction::reserve_unwatched` is called, hooks run, then `complete_with` performs teardown and ACP transcript purge. `KeptRestored` and `AlreadyGone` map to successful CLI completion; other unsuccessful dispositions `bail!`. Transcript-purge failure reports that teardown succeeded while the row was retained. `--force` only sets `force_delete`; worktree/branch deletion have separate flags (`cli/remove.rs`, `RemoveArgs` lines 9–46, `run` lines 58–225).
<!-- consolidation: discard; ref: none; reason: Upstream trash versus purge dispatch and CLI flags are external API facts. -->
<!-- consolidation: discard; ref: none; reason: Upstream successful dispositions and transcript-purge failure reporting are external outcomes. -->
2. **Reservation / concurrency:** `PurgeTransaction::reserve` acquires a per-instance lifecycle flock and updates the stored row to claim a purge generation. Restored, busy/reserved, and missing rows are rejected as `KeptRestored`, `Busy`, or `AlreadyGone`; errors acquiring/updating storage fail before teardown. `complete_inner` rechecks reservation/lifecycle. It runs teardown before deleting the durable row; if teardown fails it releases its reservation and retains the row. A changed/superseded lifecycle gates the commit. The storage row is finally removed under storage locking. On a competing delete, the winner’s reservation is authoritative; the other request gets busy/already-gone or lifecycle rejection rather than a second successful commit (`deletion.rs`, `PurgeTransaction::{reserve,gate,complete_inner}`; `session/claim.rs` is the decision helper, not expanded here).
<!-- consolidation: discard; ref: none; reason: Upstream reservation rejection and pre-teardown failure semantics are source evidence. -->
<!-- consolidation: discard; ref: none; reason: Upstream teardown-before-row-removal and retained retry state are external mechanisms. -->
<!-- consolidation: discard; ref: none; reason: Upstream competing-delete outcome does not settle this product's open concurrency policy. -->
3. **External teardown order:** `perform_deletion_core` first invokes `instance.kill_all_tmux_sessions_locked()` (or unlocked test variant); it then handles sandbox worktree preclean/container teardown and worktrees/branches, scratch cleanup, agent-store deletion only if container is gone and no accumulated errors, then hook-status cleanup. It does not remove the stored row until teardown and post-teardown work succeed. If a later worktree/container step fails, earlier external effects are not rolled back, while the row remains for retry. The tmux kill helper call has no returned result checked here; its error-swallowing behavior is detailed below. No process-group termination guarantee is claimed (`deletion.rs`, `perform_deletion_core`, `stage_teardown_worktrees`, `stage_remove_worktrees_and_branches`, `complete_inner`).
<!-- consolidation: discard; ref: none; reason: Upstream resource teardown ordering is reference evidence. -->
<!-- consolidation: discard; ref: none; reason: Upstream partial effects and swallowed kill errors are bounded source findings. -->
4. **Worktree safety and force:** unless `force_delete`, dirty managed worktrees are preserved and produce errors (which prevent purge commit). Force bypasses that dirty-worktree check, but not the default-branch preservation guard. Managed worktrees still used by another stored session are retained; path-in-use uncertainty fails closed by treating paths as in use. Branch deletion occurs only after its worktree was removed. Cleanup-on-delete and ownership flags constrain workspace deletion. ## Quit, detach, stop, delete are distinct

| Action | Source-supported distinction |
|---|---|
| Quit TUI | Input dispatch returns `Action::Quit`; `TerminalGuard::drop` restores the UI terminal state. No stop/delete/client-count teardown is invoked by this path (`tui/home/input.rs`, `tui/mod.rs`). <!-- consolidation: discard; ref: none; reason: External quit behavior is reference evidence. --> |
| Detach | Detaches one tmux client; does not stop the tmux session or the agent. No AOE last-client policy in inspected path (`tmux/session.rs::attach`; tmux client detach binding). <!-- consolidation: discard; ref: none; reason: External detach behavior is reference evidence. --> |
| Stop | `Instance::stop` takes per-instance lifecycle lock, reloads the row, reserves Stop, calls `kill_locked`, flushes conversation publication, stops sandbox container, and commits Stopped or Error. `kill_locked` stops the poller and kills the agent tmux session only if it exists; absent session is success (`session/instance/kill.rs`, `Instance::{kill_locked,stop}`). <!-- consolidation: discard; ref: none; reason: External stop transaction is not an adopted durable lifecycle schema. --> |
| Delete/purge | Shared purge transaction is destructive lifecycle operation described above: tmux sessions are asked to be killed before resource teardown; durable session row is removed only after successful teardown/commit in the normal path. Trash is a separate reversible path. <!-- consolidation: discard; ref: none; reason: External purge and trash distinction is reference evidence. --> |

Normal purge holds the per-instance lifecycle lock through the `PurgeTransaction` and invokes `kill_all_tmux_sessions_locked`. That helper kills the agent session plus ancillary terminal/tool sessions. `kill_locked` errors are debug-logged and swallowed by the uncoordinated helper; ancillary calls return no error (`session/instance/kill.rs`, `kill_all_tmux_sessions_locked`, `kill_all_tmux_sessions_uncoordinated`, `kill_ancillary_tmux_sessions_locked`; `session/deletion.rs::complete_inner`). `tmux::Session::kill` calls `kill_session_tree`; this audit does not claim process-group termination (`tmux/session.rs::Session::kill`). An attached peer’s terminal client loses its tmux session when killed; AOE does not enumerate attached clients. If kill fails, purge can continue because the helper swallows that error; later teardown failure may retain the row without undoing prior effects.

### Backlog target is deliberately different (BACK-27)

The supplied **BACK-27/spec.md** contract is task deletion = forget task and Backlog associations for every status/owner. It expressly does **not** stop/kill a provider, delete provider conversations, remove worktrees/branches, or later sweep/kill on exit. Do not transplant AOE’s runtime-session purge, kill-first ordering, resource cleanup, trash, or a new per-record purge claim. Do not resurrect associations after callbacks or reuse the deleted task ID. Parent owns validation of the actual spec/callers and writes the implementation plan; this audit does not propose a competing lifecycle redesign.
