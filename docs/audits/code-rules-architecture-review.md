# Code Rules and Architecture Review

AgenticWorkspace is a task and agent CLI/TUI documented for local multi-process use. This read-only audit found recurring parallel implementations compensated for with flags, wrappers, string parsing, and frontend policy. No audit repairs were made. Findings distinguish hard contract or instruction violations from Ponytail judgments.

This is supporting review evidence, not an accepted decision, an owning contract, or authorization to repair code or delete/reinterpret data. The findings are candidates for user review. Evidence is static only; file line numbers are audit references, not durable anchors. No runtime, provider, installed-CLI, build, or test checks are claimed.

## Must Fix

1. **Parallel compatibility lifecycle remains active.** [`controller/session-application.ts:48-50`](../../src/controller/session-application.ts) says `Core.sessions remains the compatibility route for operations this slice has not migrated`; `:103-105` exposes the getter. [`renderer/opentui/workspace-controller.ts:1791-1800`](../../src/renderer/opentui/workspace-controller.ts) routes ordinary new work to `SessionApplication` but handoff to the old path; `:1859-1864` selects a stop engine by `applicationOwned`. [`runtime/sessions.ts:846-1075`](../../src/runtime/sessions.ts) duplicates lifecycle work in [`runtime/harness.ts:184-293`](../../src/runtime/harness.ts). This violates [AGENTS no-legacy rule](../AGENTS.md#no-legacy-code), [ADR-0001:48,55](../adr/0001-model-owned-domain-behavior.md), and [Session blueprint: Harness private readiness](../blueprints/session.md). Required status coordination occurs after reserve/start in `session-application.ts:145-175`, then activates through `workspace-state.ts:115-118` while swallowing failure; that conflicts with [Sessions:122-127](../specs/sessions.md). **Consequence:** startup/reservation safety gates differ by action. **Correction:** retain one complete lifecycle with every safety gate; remove the old engine and ownership flags. **Hard violation.**
> Fix

2. **Restricted environment substitution executes a shell.** [`runtime/harness-environment.ts:17-20`](../../src/runtime/harness-environment.ts) constructs an unquoted heredoc, ``/bin/cat <<${delimiter}\n${value}:${marker}\n${delimiter}\n``; `:52-60` sends it to `/bin/sh -c`. [`harness-environment.test.ts:49-51`](../../src/runtime/harness-environment.test.ts) accepts `$PATH`, `$BASE`, `$FIRST`, and `$UNDEFINED_VARIABLE`; [`session-launch.test.ts:376-410`](../../src/runtime/session-launch.test.ts) demonstrates a `$(printf...)` side effect. [Sessions:172-186](../specs/sessions.md) allows only three reserved workspace-path references and requires other forms be rejected. **Consequence:** configuration values can execute shell syntax rather than resolve the narrow supported reference set. **Correction:** validate and substitute directly; keep an explicit preparation-command channel separate. **Hard violation.**
> Few things:
> 1. Why is this: `AGENTIC_WORKSPACE_VALUE_` still a thing? I asked a couple of times about this and haven't received an answer. Why do we need this env variable?
> 2. those env variables should just be set prior to the command execution. Either find a library that safely strips those or place those in an env file and use dotenv to load them prior to the command execution. Something safe but not ugly.

3. **Configuration inheritance has incompatible owners.** [`model/session/types.ts:156`](../../src/model/session/types.ts) replaces complete configs; [`storage/config.ts:237-239`](../../src/storage/config.ts) selects a full project config; [`renderer/task-composer.ts:211-218`](../../src/renderer/task-composer.ts) clones a complete config for one task session option; [`workspace-controller.ts:2622-2657`](../../src/renderer/opentui/workspace-controller.ts) recursively merges unknown fields through `JSON.stringify`. This conflicts with [Configuration:74](../specs/configuration.md), which requires field-wise resolution, [Models blueprint:35](../blueprints/models.md), which assigns merge ownership, and [Renderer blueprint:3](../blueprints/renderer.md), which excludes domain logic. **Consequence:** root `autoResumeOnRestart: false` can disappear; a task checkbox snapshots unrelated presets; a UI merge can restore an externally deleted optional field because an absent latest value retains stale edited state. **Correction:** one effective-config owner and typed field patches. **Hard violation.**
> Fix

4. **The running cap terminates sessions without proving idleness.** [`runtime/sessions.ts:1843-1876`](../../src/runtime/sessions.ts) collects live running sessions, sorts `useCount`/`lastUsedAt`, and kills them without current observed activity. [`agent-sessions.test.ts:1363-1376`](../../src/test/agent-sessions.test.ts) preserves this least-used eviction behavior. [Sessions:261-264](../specs/sessions.md) requires only positively idle sessions, longest continuously idle first, and protects working, permission, and unknown activity. **Consequence:** active work can be terminated. **Correction:** use the activity owner and treat usage counters as distinct from idleness. **Hard violation.**
> Fix

5. **Cleanup failures overwrite the primary error.** [`runtime/sessions.ts:1204-1228`](../../src/runtime/sessions.ts) assigns `reported = failure`, then overwrites it in each cleanup/publication catch; `:1221` explicitly establishes that precedence. [CONVENTIONS:40](../CONVENTIONS.md) requires preservation of the primary failure while exposing cleanup/release failures; [Sessions:220-223](../specs/sessions.md) distinguishes original and secondary failures. **Consequence:** callers receive misleading diagnosis and lose the cause that initiated rollback. **Correction:** retain the first error and expose subsequent failures with an aggregate/cause chain. **Hard violation.**
> Fix

6. **View-state corruption is repaired automatically.** [`storage/view-state-store.ts:186-202`](../../src/storage/view-state-store.ts) renames invalid state to `.corrupt-*` and seeds defaults. [CONVENTIONS:84](../CONVENTIONS.md) forbids automatic repair of application-produced corruption; no ADR grants an exception. **Consequence:** loading changes user data without authorization and may conceal the source corruption. **Correction:** preserve the invalid file and fail with an actionable error. **Hard violation.**
> Good catch! Fix.

7. **Configuration I/O errors become missing configuration.** [`storage/file-system.ts:867-876`](../../src/storage/file-system.ts) catches all failures and returns `null`; [`storage/storage.ts:126-129`](../../src/storage/storage.ts) treats that as absent agent configuration, although `file-system.ts:878-879` says errors are not swallowed. [Configuration:306-323](../specs/configuration.md) requires startup failure/reporting rather than substitution. **Consequence:** permission, parse, or device I/O failures silently select defaults. **Correction:** return `null` only for actual absence and propagate all other failures. **Hard violation.**
> Fix

8. **Mode deletion retains a superseded destination design.** [`renderer/agent-settings.ts:884`](../../src/renderer/opentui/agent-settings.ts) supplies a destination; [`mode-settings-draft.ts:143`](../../src/renderer/opentui/mode-settings-draft.ts) defaults it; [`model/session/mode-lifecycle.ts:155-158`](../../src/model/session/mode-lifecycle.ts) rejects every populated history; [`workspace-controller.ts:2717-2718`](../../src/renderer/opentui/workspace-controller.ts) invokes it. [Configuration:267-271,294](../specs/configuration.md) requires confirmed, preflighted cleanup then removal, with the first remaining mode as default. **Consequence:** a retained stopped session blocks deletion and the resulting default may be wrong. **Correction:** one Controller operation performs confirmed cleanup; retain the model empty-history guard only after cleanup. **Hard violation.**
> Fix

## Should Fix: Architecture and Instruction Violations

9. **Persistence ownership crosses layers.** [`model/session/mode-lifecycle.ts:1,181-182`](../../src/model/session/mode-lifecycle.ts) uses filesystem/journal operations; [`mode-model.ts:22`](../../src/model/session/mode-model.ts) constructs `SessionStore`; [`controller/agentic-workspace.ts:107`](../../src/controller/agentic-workspace.ts) retains filesystem; [`runtime/sessions.ts:234-255`](../../src/runtime/sessions.ts) and [`workspace-context.ts:216-218,261-265`](../../src/runtime/workspace-context.ts) construct paths; [`workspace-controller.ts:2533-2541`](../../src/renderer/opentui/workspace-controller.ts) uses `SessionStore` and journal; the benchmark casts into private filesystem and serializes raw records at [`scripts/benchmark-task-loading.ts:11,214-218`](../../scripts/benchmark-task-loading.ts). This violates [BLUEPRINT:26,61](../BLUEPRINT.md), [Controller blueprint:279](../blueprints/controller.md), [Renderer blueprint:63](../blueprints/renderer.md), and [ADR-0006:27](../adr/0006-layer-first-source-layout.md). **Consequence:** storage paths/codecs escape their owner and refactors have distributed breakpoints. **Correction:** Storage owns persistence, Controller sequences application work, and the benchmark uses an owned operation; retain the separate runtime-resource I/O exception. **Hard violation.**
> Fix

10. **CLI bypasses Controller.** [`cli/commands/agent-workspace.ts:3-7,40-57,68-90`](../../src/cli/commands/agent-workspace.ts) imports model/runtime/Storage and starts/asks/updates configuration directly; [`cli/register.ts:123-128`](../../src/cli/register.ts) directly reads the catalogue. [`agent-workspace-cli-routing.test.ts:51-62`](../../src/test/agent-workspace-cli-routing.test.ts) asserts that route. This conflicts with [CLI blueprint:3,51](../blueprints/cli.md): CLI calls Controller only. **Consequence:** CLI and renderer do not necessarily use the same operation or safety semantics. **Correction:** move workflows to Controller, not a forwarding callback wrapper. **Hard violation.**
> Fix

11. **Domain mutation policy is duplicated.** [`controller/agentic-workspace.ts:605-608`](../../src/controller/agentic-workspace.ts) and [`task-reorder-plan.ts:32-36`](../../src/controller/task-reorder-plan.ts) independently build moves; [`model/task/task-update/scalars.ts:5-8`](../../src/model/task/task-update/scalars.ts) accepts asynchronous callbacks; [`renderer/board/policies/column-policy.ts:65-87`](../../src/renderer/board/policies/column-policy.ts) drives persisted parent/child/order moves; [`cli/tasks/register.ts:100-105`](../../src/cli/tasks/register.ts) and [`workspace-controller.ts:2792-2800`](../../src/renderer/opentui/workspace-controller.ts) each apply Done policy. This conflicts with [BLUEPRINT:40](../BLUEPRINT.md), [Task blueprint:131,147](../blueprints/task.md), and [ADR-0001:48](../adr/0001-model-owned-domain-behavior.md). **Consequence:** mutation outcomes vary by frontend. **Correction:** resolve inputs in the application layer, then use synchronous Task/corpus policy; preserve the legitimate distinction between Done and cleanup. **Hard violation.**
> Fix

12. **Renderer revalidates agent configuration.** [`mode-settings-draft.ts:69,78-82,171-182`](../../src/renderer/opentui/mode-settings-draft.ts) duplicates validation in [`model/session/agent-config-schema.ts:7,16-28,84-192`](../../src/model/session/agent-config-schema.ts). [CONVENTIONS:81](../CONVENTIONS.md) requires one record schema rather than per-field validators, and [Renderer blueprint:3](../blueprints/renderer.md) excludes domain validation. **Consequence:** draft paths already diverge on blank purposes and duplicate validation paths. **Correction:** model schema validates; the draft retains edit state only. **Hard violation.**
> Fix

13. **Provider dispatch occurs outside adapters.** [`runtime/agents/core/profile.ts:105,124-129,152-165`](../../src/runtime/agents/core/profile.ts) switches Claude/Pi/OpenCode commands, arguments, and output grammar while adapters delegate `discoverModels` back. [Harness blueprint:79](../blueprints/harness.md) assigns executable/flags to adapters. **Consequence:** every provider addition changes shared dispatch and risks cross-provider behavior. **Correction:** keep capture provider-neutral; put provider commands/parsers in adapters. **Hard violation.**
> Amazing find!!!! Fix!!

14. **Tests require prohibited behavior.** [`search-service.test.ts:52-63`](../../src/controller/search-service.test.ts) matches High to `high`; [`task-wizard.test.ts:51-71`](../../src/renderer/opentui/task-wizard.test.ts) maps `' medium '` to Medium, conflicting with [CONVENTIONS:26](../CONVENTIONS.md) exact priority labels. [`core.test.ts:454-461`](../../src/test/core.test.ts) and [`filesystem.test.ts:138-142`](../../src/test/filesystem.test.ts) accept alphanumeric IDs despite [Tasks:79-80](../specs/tasks.md). [`core-move-tasks-to-status.test.ts:145-152`](../../src/controller/core-move-tasks-to-status.test.ts) persists milestone title `Release 1` rather than the exact milestone ID required by [Tasks:294](../specs/tasks.md). [`agent-sessions.test.ts:1387-1390,1484-1489`](../../src/test/agent-sessions.test.ts) retains a provisional record after clean preparation failure, contrary to [Sessions:202-203](../specs/sessions.md). **Consequence:** fixtures pressure implementations to weaken contracts. **Correction:** align fixtures and negative cases; do not weaken the contracts. **Hard violation.**
> Fix

15. **Test preload is a global process supervisor.** [`test/test-preload.ts:59-66`](../../src/test/test-preload.ts) uses `afterAll` to kill socket pane groups/server; [`tmux-pane-groups.ts:32-42`](../../src/test/tmux-pane-groups.ts) enumerates all pane PIDs, calls `terminateTree`, swallows errors, and does not await proof of exit. [AGENTS:97-98](../../AGENTS.md) assigns kill-and-await to the fixture that spawned a process; [CONVENTIONS:52](../CONVENTIONS.md) prohibits another global cleanup layer. **Consequence:** unrelated processes can be affected and teardown races hide ownership defects. **Correction:** preserve isolated sockets and have each fixture own teardown. **Hard violation.**
> Fix

## Ponytail Candidates

16. **Six tests use pseudo-shell wrappers.** [`cli-root-entry.test.ts:15-26`](../../src/test/cli-root-entry.test.ts), [`cli-task-view-edit.test.ts:16-27`](../../src/test/cli-task-view-edit.test.ts), [`cli-zero-padded-ids.test.ts:12-23`](../../src/test/cli-zero-padded-ids.test.ts), [`task-edit-preservation.test.ts:11-23`](../../src/test/task-edit-preservation.test.ts), [`task-search-parity.test.ts:14-26`](../../src/test/task-search-parity.test.ts), and [`task-watcher.test.ts:24-36`](../../src/test/task-watcher.test.ts) build command text through `TemplateStringsArray`, JSON encoding, regex tokenization, then call `runCli(string[])`. [`cli/register.ts:26-29`](../../src/cli/register.ts) already exposes the array API. [CONVENTIONS:58](../CONVENTIONS.md) requires unnecessary wrappers be removed. [`test-cli.ts:10-20`](../../src/test/test-cli.ts) is a subprocess helper, not an existing in-process adapter. **Consequence:** test syntax has a second, lossy argument parser. **Correction:** pass arrays directly or share the minimal required capture/serialization helper. **Ponytail judgment, not a blanket string prohibition.**
> Fix

17. **Generic edit/batch and watcher machinery appear unreachable.** CLI edit accepts one task ID at [`cli/tasks/register.ts:196,257`](../../src/cli/tasks/register.ts), but [`edit.ts:14-23,144,178-185`](../../src/cli/tasks/edit.ts) retains generic target, batch validation, and partial-failure paths. The `watch-json` command has 248 lines with no production references in the scoped `src` search, only dedicated tests. [CONVENTIONS:58](../CONVENTIONS.md) favors the smallest necessary operation. **Consequence:** unsupported surfaces retain maintenance and testing cost. **Correction:** delete unused generic/batch machinery and the orphan watcher unless an approved caller exists; do not wire them merely to justify retention. **Ponytail judgment.**
> Fix

18. **Unsupported script compatibility remains.** [`scripts/migrate-legacy-session-state.ts:4-5,28-39`](../../scripts/migrate-legacy-session-state.ts) targets the checkout-local workspace and raw-deletes obsolete fields; no package script, workflow, or source caller references it. [`scripts/cli.cjs:70-82`](../../scripts/cli.cjs) removes arguments equal to the binary path or a platform-package regex to support “global shims.” [AGENTS:28-29](../../AGENTS.md) makes legacy/migrations opt-in. **Consequence:** the migration is an unsupported destructive operation, and the launcher can drop a legitimate positional value. **Correction:** delete unsupported code, not user data. [TASK-023](../specs/tasks.md#task-023-explicit-task-and-configuration-migration) and [CONFIG-008](../specs/configuration.md#config-008-agent-settings) remain separately contracted and are not automatic cleanup targets. **Hard instruction violation for the migration; Ponytail/correctness finding for the launcher.**
> Good find!!!! FIX

19. **Focused tests sit in the shared tree.** [`test/agent-workspace-model.test.ts:3,15-31`](../../src/test/agent-workspace-model.test.ts) renders drafts; [`board-ui.test.ts:2,15-23`](../../src/test/board-ui.test.ts) covers filter policy; [`list-window.test.ts:3-11,26`](../../src/test/list-window.test.ts) uses a CLI helper. > Fix

20. **Nix pins an unsupported Bun release.** [`flake.nix:35`](../../flake.nix) sets `pinnedBunVersion = "1.3.13"`; [AGENTS:91](../../AGENTS.md) says `Bun >= 1.4 is required (CI pins 1.4.3); the 1.3 line breaks the OpenTUI suites under --parallel`. **Consequence:** Nix builds and tests differ from the supported CI/runtime line. **Correction:** align the pin and matching archive hashes with the approved Bun version. **Hard violation.**
> Fix

## Coverage and Limits

Ten read-only audit lanes reported: CLI 30 files; model/controller 68; runtime excluding adapters 42; adapters 26; renderer 47 (45 plus two large files combined); storage/filesystem 43; shared test tree 189 (A-L 59, M-Z 130, including helpers); helpers/declarations/src index/scripts/workflows 26; plus seven root config/build files. Total reported coverage is 471 code/workflow files plus seven root config/build files. Specialist inventories were reported fully read, but an independent manifest count could not be certified because one listing truncated; no lane reported unread files in its assigned scope. Colocated tests were included under their owner directories.

Dependencies, `dist`, generated `bun.nix`, and lockfiles were excluded. No test, build, installed CLI, or live-provider execution occurred. No changes were made during the audit. Recommendations do not authorize weakening runtime gates or deleting existing data. The main reconciliation is ownership consolidation and deletion of superseded paths, not another layer of flags or guards. Lean deletion candidates are the six pseudo-shell wrappers, unused batch machinery, orphan watcher, and unapproved migration; no line-savings estimate was measured.
