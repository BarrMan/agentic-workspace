## Mandatory procedure

1. **Failing area first:** apply its relevant report refactor BEFORE fixing residual failures. Read only the named finding, touched harness/source seam and callers needed for that bounded scenario. Green assertions patched against dishonest fixtures are insufficient.
2. **Fake-safety audit:** confirm transport/process/provider boundaries before any named test run. 3. **Vertical scenario:** write small named public-behavior cases with independent expected outcomes. Separate live STARTING, conclusive dead/missing, valid queued missing and uncertain observation. Preserve callback origins, exact identity/path/provider checks, no destructive observation, error nonmutation and all negative safety contracts. Do not add default-filling mega-harnesses or implementation-mirroring tests.
4. **Determinism and sensitivity:** use explicit completion fences/readiness gates instead of timing as proof. Release each gate and drain its started promise in `finally`, including assertion-failure paths. Establish prospective red/green sensitivity when needed; distinguish a controlled test-local regression from historical proof.
5. **Bounded verification:** use only the audited named suites via the repository runner and relevant type/scoped lint/diff checks. The runner's temporary compiled CLI bundle was **deleted** (`0d3ebf85`) and behaviour tests now launch the source entrypoint in a real child process (`959079a0`), so nothing is compiled for ordinary tests and a build-free runner is the current design rather than something to invent. A temporary bundle was never an installed MAIN build. Do not exercise installed source changes before the parent MAIN rebuild. Reuse valid proof; expand testing only for an unresolved concern.
6. **Finish before advance:** record changed scope, refactor result, exact proof, exclusions and remaining acceptance gaps in the finding ledger below. Verify and commit the completed slice BEFORE the next implementation slice, following the runtime plan. A reported pass from before follow-up edits is not completion evidence.

## Load starvation, the source-CLI change, and the disk incident (current)

The suite no longer compiles a CLI for ordinary tests: the shared helper launches `[bun, <abs>/src/cli/index.ts]` in a real child process, keeping pipes, exit codes, signals, PTYs and tmux panes. The built copy it replaced was also *wrong* — two suites that pass from source failed against it (`opentui-settings-persistence.integration` reported a task it had just created as missing). Cost: source launches transpile per launch, so CLI-spawning files have less headroom under 5-lane load.

Per-case budgets, measured: `agent-sessions.test.ts` is bounded at width **8** (worst loaded case 3,102 ms; width 4 was *worse* than no limit at 4,107 ms; width 16 timed out once at 10,005 ms; the fixture copy is 1.9 ms of a ~1,050 ms case). The `artifact-view-live-refresh-contract.test.ts` change in `b528462c` is **inert** — its internal 15 s budget sits inside the 10 s per-test limit — and that case awaits an OS notification with no polling fallback while asserting a 150 ms deadline; fixing it is gated on the owner's answer in the [decision sheet](decision-answers-6.md).

Open: `cli-draft-edit.test.ts` times out under 5-lane load (four sequential CLI spawns, ~3 s alone, 3 of 5 loaded runs failed; sibling CLI suites timed out in the same runs, so this is machine starvation, not a defect in that case). Investigate converting *behavioural* spawn-heavy suites to the existing in-process `runCli(argv, { cwd, stdout, stderr })` entry — `cli-guidance` went 16.1 s → 4.3 s — while keeping genuinely process-boundary suites spawning. Do not raise the per-test budget or the lane count.

Disk: the accumulation was Bun re-extracting each embedded file of a **compiled** binary (5,560,064 bytes per launch of `libopentui.dylib`; upstream Bun issue #29585), not dyld shared-cache extraction; source launches write none. Tests no longer produce it; the built/installed CLI still does (5.4 MB per launch). The runner's cross-run pruning and whole-directory preservation were removed in favour of disposable-scratch deletion plus retained per-scope ownership records, with a nonzero exit when cleanup is unresolved.
