## Agent Workspace Guide

Use this guide when opening the native workspace or managing task-scoped CLI agent sessions.

- Open the OpenTUI workspace with `agenticworkspace workspace`. OpenTUI owns the board, task list, details, and embedded agent terminals; tmux runs agent processes in the background only.
- Press `Enter` to start the selected agent or return to its retained terminal. A new session receives only `Active task: <taskId>.` followed by `Wait for user instructions.` Starting a session does not authorize task work, but it moves the task to the configured In Progress status; the workspace then follows the status tab to In Progress while keeping that task selected. Attaching to an already-running session does not change status. The agent header shows a `warming up` status before live output.
- Press `Tab` to focus the selected agent, or `f` to show its retained terminal fullscreen. `Ctrl+Q` and `Ctrl+C` leave agent input and fullscreen without interrupting the agent. `Ctrl+C` exits only from navigation. `q` never exits the workspace.
- Tasks use 30% of the workspace width. Press `Shift+[` to hide or show the task pane. Press `Space` to show or hide details in normal flow above the preview. Details use roughly 30% of the right region. Collapse expands the same retained terminal and its rows. The details border keeps the collapse hint right-aligned. Green dots mark selected and unselected tasks with active starting or running sessions only.
- Status tabs sit inside Tasks. Native Box/Text tabs follow TTT v1.6.0 `tabbar_widget.go`: the active tab is a three-row cap whose reversed bottom seams open into the task viewport, and inactive labels rest on a shared baseline at natural width plus surrounding spaces. To Do is blue, In Progress is yellow, and Done is bright green; custom statuses remain neutral. The active tab uses bold text and raised chrome without a text-background highlight. Selected tasks use dark text on light slate and remain visible when focus moves elsewhere. The Tasks title carries the count; there is no per-tab count, underline, or fixed cell. Overflow scrolls to keep the active tab visible and exposes clickable `◀`/`▶`; keyboard and mouse click navigation both work. Use `Left` and `Right` to cycle configured status tabs, wrapping at either end.
- Use `g` to select the first task and `G` to select the last. Workspace jumps stay in the current status tab; board jumps stay in the selected status pane. `Home` and `End` also work. Up/Down keeps the task-list window still until selection crosses a visible edge, then scrolls only enough to reveal it.
- Press `/` to open the opaque filter editor. Type a query, use `Tab` and `Enter` to edit choices, then apply with `Enter` from search or `Ctrl+S`. `Ctrl+R` resets the draft; `Escape` cancels. Interactive `agenticworkspace board` and `board view` use OpenTUI, including `--milestones`.
- Press `?` for keyboard shortcuts. Use `/` to search, select a row, and press `Enter`. Binding and description are separate columns in one shared responsive layout, so descriptions stay aligned. The selected row gets a native inline `Press key...` input. After the first stroke, such as `Shift+F`, the binding shows as plain text and the pending native input moves right within the same column; the footer offers an optional second stroke. A second stroke opens the unchanged Save/Discard footer. `Escape` after the first stroke confirms the single-stroke binding and removes the prompt. Pressing `Escape` twice records a single Escape binding. Use `Left`/`Right` to choose and `Enter` to apply; `Escape` discards. Overrides persist in project-local view state and replace default aliases. Ordered shortcuts run only after both strokes; conflicting shortcuts or ambiguous prefixes cannot be saved. Discard and failed saves keep the previous binding.
- Press `s` for the selected task's sessions, newest first with the active session marked. Select a session to display its retained terminal or resume its exact saved conversation. No “latest conversation” fallback is used.
- Workspace and `agenticworkspace agent-session` commands share durable session records and output. Normal workspace exit, `SIGINT`, and `SIGTERM` wait for owned-agent teardown, including children that ignore `SIGHUP`; their records remain available for exact resume. Stop failures remain explicit and retain process handles instead of falsely marking a session stopped. A pre-existing private tmux server is refused and left untouched. Selecting a task whose CLI-owned session is still running attaches its real pane automatically, with no `Enter`, start, resume, or ownership change; returning keeps the same preview. A stopped task does not auto-resume. Leaving the workspace detaches externally owned previews without stopping their sessions. `SIGKILL` and hard crashes cannot run cleanup handlers.
- The agent backend is always the default tmux server, so a workspace running inside another tmux server still attaches the real agent. `agenticworkspace agent-session attach` switches the client only when already attached to that same server; otherwise it attaches a new client instead of switching.
- Press `,` for fullscreen project-only Settings. Rounded category and content panes use cyan focus; `Agents` is the only category. Press `Right` to enter fields and `Left` to return to categories. Use `Tab`/`Shift+Tab`, `Up`/`Down`, or mouse clicks to select a read-only field. Press `Enter` to edit. Preset arrows change options only while editing; text fields become native inputs. Press `Enter` again to commit the field, or `Escape` to cancel its edit. Paste multiline environment values or use `Shift+Enter` for a newline if your terminal supports it. At the preset selector, `Space` marks the chosen preset as default. `Ctrl+S` saves only committed draft values. `Escape` outside editing discards the whole draft. User-level settings are not exposed.
- Task creation inherits project configuration unless a preset is selected. Press `p` to choose a task override or restore inheritance. Existing sessions retain their original preset snapshots for exact resume.
- Press `h` to select a replacement preset before handing off the selected task. Handoff stops the active session and starts a fresh active one; a failed launch leaves a stopped record rather than reactivating the predecessor.
- Use `agenticworkspace agent-session list BACK-123`, `start BACK-123`, and `stop BACK-123` for CLI lifecycle actions. Use `output BACK-123` to read persisted output or `attach BACK-123 --session <id>` to attach to a selected session.
- Ask the previous (most recent non-active) session a question with `agenticworkspace agent-session ask <taskId> "<question>" [--session <id>]`; its answer prints on stdout. `--session` selects a specific session, a running or starting session must be stopped or parked first, and the target must have a resumable native session identity.
- Run `agenticworkspace skill` to print the Backlog Task Management skill. Task-manager launches load it through a temporary session-scoped skill directory, never through global or project-wide skill installation. The active task is the durable source of truth; update its requirements, decisions, progress, verification, blockers, and next steps through the AgenticWorkspace CLI.
- Session-local skill loading is available for OpenCode, Claude, and Pi.
- Configure a provider's exact resume syntax with `agenticworkspace agent-config set <scope> --resume-flag <flag>`. Existing presets without `resumeFlag` retain their provider defaults. AgenticWorkspace never resumes a “latest” session.
- Replace an active CLI session with `agenticworkspace agent-session handoff BACK-123`. Handoff stops the active session and starts a new active one; there is no detached worker. Use `reconcile BACK-123` to settle dead sessions.
- New task-manager launches run from the project root, not task worktrees. The CLI can resolve that root through `BACKLOG_CWD`, but the agent environment removes task/project metadata variables: `BACKLOG_CWD`, `BACKLOG_TASK_ID`, `BACKLOG_SESSION_ID`, `BACKLOG_PROJECT_ROOT`, `TASK_ID`, and `SESSION_ID`.

Consult `agenticworkspace agent-session --help` or `agenticworkspace agent-config --help` as needed.
